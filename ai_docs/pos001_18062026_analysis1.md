| Model | Fungsi | Kunci Asing | Unique Fields |

| `Owner` | User/admin | — | `email` |

### 2.3 Temuan & Catatan Penting

#### Potensi Masalah

| # | Temuan | Detail | Risiko |
|---|--------|--------|--------|
| 1 | **Category tidak punya unique constraint** | Field `name` per owner bisa duplikat (dua "Kaos" untuk owner yang sama) | Menengah — perlu penanganan di application layer |
| 2 | **Supplier tidak ada unique constraint untuk name+ownerId** | Sama seperti Category | Menengah |
| 3 | **Product tidak ada SKU unique** | `sku` bersifat nullable dan tidak unique, bisa null untuk semua produk | Rendah — SKU opsional sesuai spesifikasi |
| 4 | **TransactionItem.costAtPurchase** | Menyimpan snapshot harga modal saat pembelian — bagus untuk historical tracking | OK — ini pattern yang benar |
| 5 | **Product.variants & bundleProducts berupa String** | Menyimpan JSON sebagai string (bukan JSON field) — Prisma SQLite tidak support JSON type | Rendah — acceptable untuk SQLite |
| 6 | **StockMovement.type** | Menggunakan String, bukan Enum | Menengah — raw string rentan typo |
| 7 | **Transaction.status** | Menggunakan String default "completed", bukan Enum | Menengah — raw string rentan typo |
| 8 | **Tidak ada cascade delete** | Hanya `TransactionItem` yang punya `onDelete: Cascade` dari `Transaction`. Relasi lain tidak ada cascade | Aman — hindari delete owner yang punya data |
| 9 | **AIInsightCache expiresAt** | Tidak ada index terpisah untuk query cleanup | Rendah — data relatif sedikit |

#### Positif dari Skema

- ✅ **UUID sebagai primary key** — aman untuk distribusi, tidak conflict
- ✅ **Snapshot harga di TransactionItem** — `costAtPurchase` dan `unitPrice` terpisah dari Product, sehingga historical data akurat meski harga berubah
- ✅ **AIInsightCache punya composite index** — query `(ownerId, type, period)` sudah dioptimasi
- ✅ **Relasi sudah tepat** — cascade hanya di TransactionItem (hapus transaksi = hapus itemnya)
- ✅ **Flexible nullable fields** — `categoryId`, `supplierId`, `sku`, `variant`, `notes` semuanya nullable

### 2.4 Rekomendasi Perubahan Skema

```
1. Tambah unique constraint untuk Category:
   @@unique([ownerId, name])

2. Tambah unique constraint untuk Supplier:
   @@unique([ownerId, name])

3. Pertimbangkan enum untuk StockMovement.type:
   type: String // sebaiknya: "IN" | "OUT" | "ADJUSTMENT"

4. Pertimbangkan enum untuk Transaction.status:
   status: String // sebaiknya: "completed" | "voided" | "pending"
```

## 5. Analisis Coding Rules (RULES.md)

### Aturan Kunci yang Harus Diperhatikan

| Aturan | Ringkasan |
|--------|-----------|
| **Komentar** | Hanya untuk syntax/logika yang tidak obvious |
| **Typing** | `type` untuk data shape, `interface` untuk kontrak. Tidak pakai `any` |
| **Anti-AI Patterns** | ❌ Naming verbose, ❌ Destructuring tidak perlu, ❌ Guard berlapis, ❌ Abstraksi prematur |
| **DRY** | 3x duplikasi = abstraksi |
| **Ukuran** | Max 300 baris/file, 20 baris/fungsi, 3 parameter/fungsi |
| **Error Handling** | ❌ Jangan swallow error, ❌ Jangan bypass TS, ❌ Jangan silent skip |
| **Early Return** | Tolak kondisi buruk duluan, logic utama di level 0 |
| **No console.log** | Gunakan proper logger |
